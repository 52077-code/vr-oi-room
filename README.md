# VR OI 考场 · 重制版

第一人称虚拟 NOI 考场。四小时、四道题、四百分；能写代码、能喝水、能去洗手间、
能干扰同学偷看他的代码、能举手喊老师 —— 也能一拳把监考老师放倒，然后被两百名保安追着打。

原版参考：<https://aakaakii.github.io/vr-oi-simulator/>（分析用镜像在 `../vr-oi-simulator/`）。
本目录是**按同一套玩法、重新实现**的版本：代码全部重写，架构、物理、判题、
灯光与后处理都换了自己的做法，并补了原版没有的东西（见文末差异清单）。

## 怎么跑

**必须用 http:// 或 https:// 打开**，`file://` 下浏览器会拒绝加载资源、`localStorage`
也不可用（存档直接失效）。`index.html` 内置了这条检查：用 `file://` 打开会直接给出
可照抄的命令，不会留你对着白屏。

最省事的办法：**双击项目根目录里的 `serve.cmd`**。它会切到自己的目录、检查 Node 在不在、
起服务、顺手打开浏览器，关掉那个黑窗口就是停服务。

命令行版（等价）：

```powershell
cd D:\朕的api\vr-oi-room
node tools/serve.mjs                             # 推荐：装了 Node 就能用，零依赖
```

然后浏览器打开 `http://127.0.0.1:8848/`。判断标准：地址栏是 `http://` 或 `https://`
就对了，是 `file://` 就错了。

> `serve.cmd` 里刻意只写 ASCII：cmd.exe 默认走 OEM 代码页（简中系统是 936），
> 批处理文件里的中文会变成乱码；而 `.cmd` 必须是 CRLF 行尾，
> 用 LF 存会让 `if (...)` 这种括号块解析出错。这两条都踩过。

> **强烈建议用 `tools/serve.mjs`，而不是 `python -m http.server`。**
> 不是功能问题 —— python 那个能跑。问题是它**不发任何缓存头**，浏览器于是启用
> "启发式缓存"，会把 `js/*.js` 留在本地反复复用。结果就是：你改了代码、刷新、
> 控制台报的错还是旧代码里的，排查方向直接被带偏。本项目真的被这一条咬过一次，
> 所以 `serve.mjs` 现在会**自动**做版本破除：启动时算出所有源码的 BUILD_ID，
> 把 `index.html` 里所有 `?v=` 重写成它；带戳的资源长缓存，入口页 no-store。
> 只要动过任何源码文件，URL 就变，浏览器必然重新拉取，不需要任何手动操作。

**版本戳也在界面上**：开始界面底部有一行很小的 `构建 xxxxxxxxxx`。它的唯一职责是
让"浏览器还在跑旧缓存"这个判断变成一次目视比对 —— 如果这行显示的不是你刚改的版本，
那就是缓存问题，不是代码问题。同一份信息也打印在控制台，并出现在启动失败横幅里。

`three.js` 由 index.html 里一个**静态阻塞式标签**加载，默认是本地
`vendor/three.min.js`（零网络依赖、离线可用）。如果这个文件丢了，把标签的 `src`
换成注释里列的任意一个 CDN 地址即可。**不要**把它改回"动态插入脚本异步加载"——
原因见下一条。

## 想要 https？

先说结论，省得你白折腾：

**这个项目不需要 https。** 它在 `http://127.0.0.1` 下已经是完整功能的。
原因是 **`127.0.0.1` 属于环回地址，Chrome 本来就把它当作"可信来源"（trusted origin）**，
安全上下文该有的东西它全都有。实测数据：

| | `http://127.0.0.1:8848` | `https://127.0.0.1:8443` |
| --- | --- | --- |
| `isSecureContext` | **true** | true |
| `localStorage` 可写 | **可用** | 可用 |
| Pointer Lock / Fullscreen | **可用** | 可用 |
| Console 警告 | 无 | 无 |

真正会出问题的是非环回的情况：局域网 IP（`http://192.168.x.x`）、自定义域名、
手机访问电脑。那种情况下 `isSecureContext` 才是 `false`，`localStorage` 直接抛错。
**如果你是因为要从别的设备访问、或者想用域名，才需要 https。**

### 做法：自签证书 + 本地 HTTPS 服务

```powershell
node tools/gencert.mjs        # 签发证书（纯 Node，不需要 openssl / mkcert）
node tools/serve-tls.mjs      # 起 https://127.0.0.1:8443/
```

`gencert.mjs` 手工拼 DER 签出 X.509 证书，SAN 覆盖 `localhost` / `127.0.0.1` / `::1`，
签完会**立刻用 Node 的 `X509Certificate` 读回来自检 9 项**（解析、subject、有效期、
自签验签、SAN 逐项）。证书有效期默认 3650 天，产物写在 `certs/`（已在 `.gitignore` 里）。

> **重新签发证书后不用重启 `serve-tls.mjs`。** 它每秒比对 cert/key 的 mtime，
> 变了就用 `server.setSecureContext()` 热替换 TLS 上下文（Node 11.6+ 的公有 API），
> 新连接立即拿到新证书。
> 想确认"服务器现在实际提供的是哪份证书"：`node tools/certinfo.mjs 8443`。
> （做这个热重载是因为：证书只在启动时读入内存时，重新签发后浏览器拿到的还是旧证书，
> 会出现"指纹怎么刷都一样"的假象 —— 这个坑在一次会话里咬了两次。）

**首次打开一定会看到安全警告**，这是自签证书的固有代价，不是配置错了：

> 您的连接不是私密连接 / `NET::ERR_CERT_AUTHORITY_INVALID`
> → 点「高级」→「继续前往 127.0.0.1（不安全）」

因为自签证书不在任何受信任根里。**想彻底消掉警告**，唯一正路是把你的根证书装进系统
信任区，工具是 [mkcert](https://github.com/FiloSottile/mkcert)（会自动装）。它签出来的
证书同样丢进 `certs/cert.pem` + `certs/key.pem`，`serve-tls.mjs` 不用改一行。

> 顺带一个坑：**`file://` 不是"更安全的本地打开方式"**，它反而最糟 ——
> 拿不到安全上下文，`localStorage` 抛错，资源加载也被拦。

## 排查：启动失败

`js/boot.js` 里完整记了 three.js 加载方式的**三次踩坑**，因为前两次的做法看起来
都对、报错却都指向别处。结论表：

| 症状 | 真因 |
| --- | --- |
| `THREE is not defined` at `core.js:…` | three 是**异步**到达的。core/world/player 在模块顶层就 `new THREE.Raycaster()`，解析器不会等它 |
| `Cannot access 'mouseSens' before initialization` | **二次伤害**。上一条让模块级 `let` 全部没执行到，之后任何路径碰到它就报这个。它和 three 的加载顺序没有任何表面联系 |
| 全屏空白，只有一行英文报错 | 页面是用 `file://` 打开的 |
| 报错文字里提到 `THREE_SOURCES` / `cdn.jsdelivr.net`，但代码里已经搜不到这些字 | **浏览器在跑缓存的旧文件**。看开始界面底部的版本戳，或按 `Ctrl+Shift+R` 强制刷新 |

正确做法只有一个：**three.js 必须在 boot.js 被解析之前同步加载完**，也就是用静态
`<script>` 标签。静态标签没有等待、没有时序不确定性。

> 排查心法：**先用取证排除"跑的是不是当前代码"，再去看代码本身。**
> 一条报错如果只存在于你已经删掉的旧文件里，那把代码读十遍也没用。
> 本项目两次耗时最久的排查，根因都在"跑的不是当前代码"上（一次是异步加载，
> 一次是浏览器缓存），两次的症状都指向了完全无关的位置。

## 排查：鼠标"失灵"、点了没反应

这个项目用的是 **Pointer Lock**（指针锁定）：鼠标移出画面也不会丢，视角才会跟着转。
它和普通网页的交互状态是两套东西，所以"鼠标失灵"在 99% 的情况下不是坏了，
而是**当前没锁上**。按现象对照：

| 现象 | 真正的原因 | 怎么恢复 |
| --- | --- | --- |
| 画面还在，但鼠标动不了视角、点击没反应 | 没处在指针锁定状态 | **点一下画面**重新锁定 |
| 点一下还是没反应 | 刚按过 `Esc`。浏览器有约 **1.25 秒冷却期**，期间 `requestPointerLock()` 会被**静默拒绝** | **等 1 秒，再点一次** |
| 屏幕上有"鼠标未锁定"的提示 | 同上，冷却期还没过 | 等提示消失后点画面 |
| 出现暂停菜单 | `Esc` 会开菜单，这是设计如此 | 点「返回考场」，或再按 `Esc` |
| 完全点不动、键盘也没用 | 窗口失去焦点（切到了别的程序） | 点回浏览器窗口 |

> **为什么冷却期这么容易踩：** `requestPointerLock()` 在刚 `Esc` 之后会被拒绝，
> 而且拒绝是**静默**的 —— Promise reject、`pointerlockerror` 事件，界面毫无变化。
> 玩家的体验就是"鼠标彻底坏了"，完全无从判断该等一等还是该刷新页面。
> 现在 `Mousedown` → 申请锁定，失败会在画面上给出可执行的提示
> （"稍等约 1 秒再点一次画面"），不再让你对着一个没有反馈的画面反复乱点。
>
> 另外左键只用 `mousedown` 而不是 `click`：`click` 要求"按下与抬起落在同一元素上"，
> 而锁定后视角会瞬移，手一抖就成了拖拽，`click` 根本不触发 —— 表现同样是"点了没反应"。

## 排查：服务器挂了 / 想重新打开

`http://127.0.0.1:8848` 打不开，通常是**那个终端窗口被关掉了**。重开一个即可：

```powershell
cd D:\朕的api\vr-oi-room
node tools/serve.mjs                              # http://127.0.0.1:8848/
```

想关掉它：

```powershell
node tools/serve-stop.mjs                         # 关 8848 + 8443
node tools/serve-stop.mjs --list                  # 只看谁占着，不动手
node tools/serve-stop.mjs --all                   # 扫全盘，关掉本项目所有 serve
```

`serve-stop.mjs` **不会按端口号盲杀**：先查到占用端口的 PID，再核对它的命令行
确实是本项目的 serve 脚本，两条都满足才动手，对不上就只报告、不杀。
（命令行匹配刻意用 ASCII 的文件名 `serve.mjs`，不去匹配带中文的项目路径，免得踩编码。）

> 能看到启动窗口的话，直接在那个窗口按 `Ctrl+C` 是最简单的关法。
> 但如果服务是用 `Start-Process` / 后台起的，就**没有窗口可按** ——
> 这时用 `serve-stop.mjs`，或者：
>
> ```powershell
> Get-NetTCPConnection -State Listen -LocalPort 8848 | Select-Object LocalPort,OwningProcess
> Stop-Process -Id <上面查到的 PID>
> ```


想要 https，第二条命令（**首次需要先签证书**）：

```powershell
node tools/gencert.mjs                            # 只在 certs/ 不存在时需要
node tools/serve-tls.mjs                          # https://127.0.0.1:8443/
```

`serve-tls.mjs` 会**热重载证书**（每秒比对 mtime，用 `setSecureContext()` 热替换），
所以重新签发之后**不用重启**它。想确认服务器当前实际提供的是哪份证书：

```powershell
node tools/certinfo.mjs 8443
```

端口被占用（`EADDRINUSE`）时换一个端口即可，两个脚本都接受端口参数：

```powershell
node tools/serve.mjs 9000                         # http://127.0.0.1:9000/
```

> 再重复一次：**玩这个项目不需要 https。** `http://127.0.0.1` 本身就是
> Chrome 认可的"可信来源"（环回地址），`isSecureContext` 已经是 `true`，
> `localStorage`、Pointer Lock、Fullscreen 全都能用。只有当你要从**别的设备**
> 或**域名**访问时才需要它 —— 见上面「想要 https？」一节。

## 验证

三个工具，由浅入深。改动后建议按顺序都跑一遍。

```powershell
node tools/tdzscan.mjs        # 静态：跨文件暂时性死区 / 重复声明（秒级）
node tools/smoke.mjs          # 无头：逻辑与状态机（快，可跑几十轮找偶发）
node tools/browsercheck.mjs   # 真浏览器：真实 three.js + WebGL（需先起服务）
```

**`tdzscan.mjs`** —— 本项目用传统 `<script>` 共享全局作用域，所以后加载文件里的
`let/const` 对先加载文件而言处于"暂时性死区"。扫描器先做一遍词法净化（把注释 /
字符串 / 正则 / 模板串抹成等长空白，行号严格对齐），再按花括号深度分出"文件顶层"
与"函数体内"，然后检查三种问题：同名重复声明、顶层语句引用后声明的词法名、
函数体内引用后声明的词法名。**这就是 `mouseSens` 那个坑的来源。**

**`smoke.mjs`** —— 最小 DOM 桩 + 最小 THREE 桩，把全部 35 个逻辑脚本放进同一个 vm
上下文执行，驱动主循环并走完整条流程（校园 → 传送圈 → 安检 → 404 → 桌面 → 小恐龙 →
写码 → 提交 → 打老师 → 保安 → 弹窗 → 结算 → 存档 → 打满 200 → 补给 → 用光再捡 → 快捷栏不变式 → 名次 → 老师的那一眼 → 员工通道 → 手机 → 入场截止 → 手机物品与 2048），105 项断言。
抓的是未定义函数、拼错变量、调用了不存在的 API、状态机不收敛。

> **它跑 20 遍必须 20 遍全绿。** 凡是要靠"多跑几次才对"的断言，都属于测试自己不可靠：
> 有的是桩的 `Clock.getDelta()` 读真实墙上时间（测试循环比真实时间快，`dt≈0`，
> 跳跃/移动永远走不完），有的是断言依赖了随机生成的位置（保安被刷在课桌旁会卡住，
> 而那正是真实的滑墙行为）。正确做法是把不确定性从断言里挤出去 ——
> 喂确定性的 `dt`、把被测对象放到确定的位置 —— 而不是把门限放宽。

> 它开头先做一遍 **THREE 桩覆盖度自检**：把项目代码里用到的每个 `THREE.Xxx`
> 和桩提供的键对一遍，缺了就直接列名字。这一条是补上来的 ——
> 桩缺类时抛的是 `Xxx is not a constructor`，位置指向毫不相关的业务代码，
> 而且会让后面所有顶层 `let` 全都没初始化，二次伤害出的是
> `Cannot access 'mouseSens' before initialization` 这种完全误导的错。
> 实测这个自检一次揪出 `Object3D`（虽然那处只是注释里提到），
> 在此之前逐个试错花了七八轮。
>
> 桩的元素要能派发 `document` 级键盘事件，且事件对象默认带 `isTrusted: true`
> —— 小恐龙的按键路由就是这么被测到的（要验"合成事件被拒"时显式传 `false`）。

**`browsercheck.mjs`** —— 用 CDP 驱动真实 headless Chrome，拿真正的
console / exception，并在页面里直接读运行状态。它测的是桩测不出来的东西：
真实 three.js API 差异、真实 WebGL 渲染路径、真实射线拾取。它会报出一帧内有几个
pass、多少 draw call、弹窗 mesh 在哪一层、紧张值把画面调成了什么参数。
最后两节专门盯"画出来的"和"会撞的"是否一致：小恐龙的腿有没有接在身体上、
判定盒有没有伸到画面之外、像素有没有画穿地面线、画布是不是整数倍缩放。
另有一节用**真按键事件**（`B` / `1`-`4` / `Q`）走一遍背包与快捷栏 ——
数据模型对不对 `smoke.mjs` 能测，但"快捷栏里到底有没有 4 个格子""按 B 关不关得掉"
只有真 DOM 才看得出来；事实上有条 bug（`B` 关不掉背包）就是这么抓到的。
同一节还验证补给物真的挂进了场景、真的走过去捡得到 —— 这一幕桩测不出来。
另外两节专盯"桩看不见"的东西：**HUD 上的名次到底画出来了没有、那一行会不会被挤得折行**，
以及**走真实的 `openDesktop()` 打开电脑、让老师踱到座位旁，桌面是不是真的被关掉了** ——
后者尤其只能真跑，`closeDesktop()` 会把视图退回 IDE 还是退回世界，桩里读不出来。
最后一节才做结算：`endContest()` 会清存档、清保安、置 ended，放在中间会把后面几节的前提全拆掉。

> 桩测试绕过了 `boot.js`（它只负责加载），所以**桩测试全绿 ≠ 浏览器能打开**。
> `browsercheck.mjs` 是唯一覆盖加载时序那一层的工具——这个 bug 就是这么漏出去的。

**`dinomap.mjs`** —— 小恐龙的渲染体检。像素画"看起来对不对"很难靠读坐标判断，
所以它把 canvas 上的实际结果**扫成字符画打出来**（一个字符 = 一个位图像素），
并逐项量出："腿接在身体的哪个位置""判定盒有没有伸到画面之外""有没有画穿地面线"。
它还会用 `getImageData` 把身体和腿**分开画、分开量** —— 画在一起时，
腿悬空 16px 这种事在小图上根本看不出来。

> 关键约束：探针**不许自己抄公式**，一律调 `dinoCactusGeom()` / `dinoBirdGeom()` /
> `DINO_BIRD_HEIGHTS`。抄一份常量就等于给自己准备了一个会说谎的裁判
> （真实教训见下面对应那条）。
>
> `dinoshot.mjs` 是它的兄弟：把 6 种姿态导出成 PNG，用来给能看图的人复核。

**`dinoart.mjs`** —— 改美术时的草稿纸。它不起浏览器：直接从 `js/launcher.js` 里
把 `DINO_BODY` / `dinoCactusGeom` / 那几个 draw 函数抠出来，用自己实现的最小
2D 画布（只有 `fillRect`）重放一遍，打成字符画。改一行位图、跑一次、看一次，
迭代不到一秒。它也顺手做体检：位图必须 24 行 × 32 列、最后一行的腿位置必须有实体、
"内部空洞行数"必须 ≥ 2（眼睛和嘴就是靠挖洞画出来的，0 就意味着那张脸没有五官）。

> 它的输出里有一段"候选位图画成可以直接粘回 `launcher.js` 的字面量"——
> 24 行手数字节很容易数错一格，让工具生成就不会。
>
> 最后仍要跑一次 `dinomap.mjs`：`dinoart.mjs` 验的是"位图长什么样"，
> `dinomap.mjs` 验的是"真 canvas 上画出来是不是同一个东西"。

## 开发过程中被工具抓到的真实 bug

- **小恐龙的跳跃顶点比障碍还矮 —— 一个都跳不过去。** 判定盒底面要越过障碍顶面，
  也就是 `dinoY ≥ 障碍高度`：最矮的仙人掌 58px、最高的 74px，而 `JUMP_V=440`
  的顶点只有 **50px**。竖直方向永远差一截，**任何时机起跳都是必死**。
  原来那段常量注释只算了水平位移（"最宽 57px，留了约 100px 余量"），
  从头到尾没算过竖直余量。而测试里那条 `最高速滞空位移够跨最宽仙人掌` 犯的是
  **同一个错**：它也只比"位移 vs 宽度"（纯水平）。于是代码和测试互相印证着同一个
  错误假设，一路全绿，玩家却跳不过任何东西。`JUMP_V` 改 700（顶点 130px，余量 56px）。
- **障碍间距是固定距离，不随速度缩放 —— 会空中撞死。** 跳跃要求 `dinoOnGround`，
  而滞空跨度 = 速度 × 滞空时间，速度越快跨度越长；间距却是写死的 190~430px，
  于是高速时第二个障碍会在你还在空中时贴到脸上，**没有任何操作空间**。
  注释里写的意图明明是"保证反应时间不随时间下降"，代码却用了固定距离，正好写反。
  改成 `间距 = 速度 × 滞空时间 + 150`（随机浮动仍在）。这条还加了断言：
  采样真实生成的间距，逐行比对它自己那个速度所需的跨度。
- **蹲下时小恐龙的腿悬在身体下方 16px，还戳穿地面线 13px。**
  腿的纵向基准写的是绝对像素（`y + 22*s` / `y + 24*s`），而身体的高度是
  `24*s*sq` —— 两者没共用那个挤压系数。站姿下 `24*s` 恰好等于身体高度，
  所以看不出问题；蹲姿身体只剩 `24*s*0.58`，腿却还按老位置落位，于是
  **腿悬在身体底下 16px、并戳到地面线以下 13px**：看起来是一个压扁的身子
  浮在两条断腿上面。修法是把 `0.58` 收成 `DINO_SQUASH`，身体/腿/`bodyY`
  三处共用，腿的基准改成"压扁后身体的底部"。现在蹲下整体高 40px（原来 54px，
  和站姿的 60px 几乎一样高 —— 蹲了跟没蹲一样）。
- **"成组仙人掌"的判定盒是它画出来的两倍宽 —— 没碰到就死。**
  绘制按 `o.w` 居中，但实际只画出 **25px**；判定盒却用 `o.w - 8` = **50px**。
  `o.w` 对画面几乎没有影响（只改主干粗细 10/8、侧枝 2/1），所以
  "成组"和"单株"看起来一样宽，而它两边各有 **12~13px 的无形杀伤区**。
  代码里那段注释写的是"用满尺寸的盒子会让『看起来擦过去了却判死』"，
  实际做的恰好就是它声称要避免的事。改成一份 `dinoCactusGeom()` 同时喂给
  绘制和碰撞，并且让 `w` 真的有视觉含义（成组 = 三根主干铺满 `o.w`）。
- **低飞翼龙的翅膀会画到地面线以下 11px。** 扇翅有两帧，向下的那帧最低点
  落在 `by + 34`；`GROUND-22` 这种高度就会让翅膀穿出地面。
  飞行高度收进 `DINO_BIRD_HEIGHTS`（生成器和测试共用），最低那档抬到
  `GROUND-36`，约束就一条：**向下扇翅那一帧也必须留在地面线以上。**
- **像素画被非整数拉伸。** `#dinoCanvas` 用 `width:100%` 跟着容器走，
  容器给 910px 而内部是 900px → 缩放 **1.0111**。配上
  `image-rendering:pixelated`，意味着一个源码像素映射到 1.0111 个设备像素：
  同一张图里有的列摊 2 个设备像素、有的只摊 1 个，大片纯色出现摩尔纹、
  所有竖边粗细不匀。改成 `dinoFitCanvas()` 取容器放得下的**最大整数倍**，
  窗口尺寸变化时重算。
- **仙人掌的绘制坐标是分数。** `o.h*0.32`、`o.h*0.46`，以及 `o.w` 为奇数时
  算出的 `404.5` —— canvas 上这些坐标会被抗锯齿摊成两列 50% 灰，
  表现就是**边缘发虚**。现在 `dinoCactusGeom()` 里所有坐标和尺寸一律取整。
- **探针自己抄了一份常量，于是量的是探针的假设、不是游戏的行为。**
  `dinomap.mjs` 第一版把翼龙高度和仙人掌判定盒的公式又写了一遍，
  结果在代码已经修好之后仍然报"翅膀穿地 11px""右侧隐形杀伤 2px" ——
  全是假的。改成一律调 `dinoCactusGeom()` / `dinoBirdGeom()` / `DINO_BIRD_HEIGHTS`。
  这条和上面"测试和代码互相印证同一个错误假设"是同一类病：
  **重复一份常量，就等于给自己准备了一个会说谎的裁判。**

- **停留进度环会永久卡在屏幕上。** 进度环的显示条件是 `dwell.progress > 0.002`，
  而清进度的代码只在 `closeDialog` 的"关掉的正好是当前悬停弹窗"分支里 ——
  但点鼠标走的是 `activateDialogButton()`，它**先把 `dlgHoverBtn` 置空**再调回调，
  回调里再 `closeDialog` 时那个判断恒为假，进度永远清不掉。
  而本该兜底的"下一帧 `updateDialogs`"也不成立：`main.js` 里它被
  `if (dialogs.length)` 挡着，弹窗一关就再也不跑。
  按"视线停留"正常走满不会复现（那条路径自己把进度归零了），
  **只有提前打断才留下半格** —— 这就是为什么它表现为"提前点鼠标才会卡"。
  修法是把清进度收成一个 `resetDwell()`，在四个该清的地方都调，并让
  `updateDialogs` 无条件每帧执行（它不只是"追随弹窗"，还负责维持状态合法）。
- **校园弹窗的选项回调漏了 `closeDialog`，一次搞坏三件事。** `doSecurityCheck` /
  `enter404Classroom` / `talkToVolunteer` 的每个选项都只写了副作用，没关弹窗
  （项目里其它弹窗都写了 `cb: dlg => closeDialog(dlg)`，只有校园这三处漏了）。
  弹窗于是永久留在屏幕上，而 `hasDialog()` 一直为真：
    ① 点击被 `onPrimaryDown` 最前面拦掉 → **鼠标"失灵"**；
    ② E / 数字键只是反复触发同一个选项，窗还在 → **"对话框关不掉"**；
    ③ `campusInteract` 再也不执行 → 碰不到门 → **"进不了楼"**。
  三个看似无关的症状，同一个根因。
  **教训：测试只断言了"动作的副作用"（`passedSecurity` / `area`），从不断言
  "状态机的出口"。** 补上后才能挡住这一类 —— 断言要覆盖弹窗真的消失了。
- **`onPrimaryDown` 把点击从弹窗手里抢走了。** 弹窗自己声明的消除方式里明明有
  "点按钮"，但点击在函数最前面就被 `return` 吞掉，等于自断一条路。
  现在有弹窗时点击交给 `activateDialogButton()`；无按钮的纯文本弹窗则由
  `dismissPlainDialog()` 兜底，避免又一种"只剩 Esc 一条路"的卡死。
- **提示文案漏了内部英文标识**：`'[ E ] 过安检（' + rec.kind + '）'` 会渲染成
  `过安检（audit）`。改成用 `label`（安检门 / 楼门），内部标识不再漏给玩家。
- **`Renderer` 桩的 `domElement` 是个空壳**：`addEventListener` 收下监听器却直接
  丢掉，`dispatchEvent` 又不存在。于是"点击画面"这条路径在测试里**从来没被真正
  执行过**，测试全绿只是因为空跑 —— 这才是上面那批鼠标 bug 能漏过去的原因。
  现在桩真的存监听器、真的派发，并断言 `__handlerCount('mousedown')` 不为 0。
- **版本戳在启动时被冻结**：改了源码刷新页面，界面上那行 `构建 xxxxxxxx` 纹丝不动，
  于是会去怀疑缓存；而服务器还在按旧 ID 发 `?v=`，浏览器便合法地复用旧资源。
  **"判断依据"本身变成了误导源。** 改成每请求现算，用 mtime 摘要挡住重算。
- three.js 异步加载导致全线 `THREE is not defined` → 改用静态阻塞式标签；同时把
  跨文件共用的常量（`PUNCH_ARC`、`GUARD_PUNCH_RANGE` 等）统一收进 `core.js`，
  从根上消灭"声明在后面文件"这一类隐患。
- `debris.js` 用 `THREE.Matrix4().decompose` 取部件位姿，在部分 API 暴露下会静默
  拿不到位姿 → 改成显式按部件世界矩阵分解。
- `ide.js` 的评测轮询写成 `const iv = setInterval(() => { … clearInterval(iv) … })`，
  首次回调若早于赋值会抛 TDZ 错误，且只在"进度跑满的那一帧"才炸。
- `world.js` 里 `const doorGroup = …` 遮蔽了模块级变量，终局开门动画永远操作不到门。
- `tension.js` 的"坐定了"判定坐标基准和实际座位差了一格，平静通道形同虚设。
- 开门后身后的追兵仍能把玩家抓走 —— 打赢了 200 人却被系统坑，逻辑与体验都说不通。
- **`AREA_BOUNDS.campus` 写成局部坐标，而玩家位置是世界坐标。** 校园整体平移到
  `+Z 500`，边界表里却只写了 `-29.2 ~ 15.2` —— 钳制框和玩家根本不在同一段空间里，
  每一步移动都被钳回出生点，人完全走不动。这类"两套坐标系混用"的错不会报异常，
  只会表现为"手感不对"，靠人眼排查极难；`smoke.mjs` 里一条"出生点在可行走范围内"

- **`buildPerson()` 返回的是字面量对象，没有 `userData`。** `p` 不是
  `THREE.Object3D`（只有 `p.group` 是），但调用方看到"人物对象"很自然会写
  `p.userData.xxx`。初值补在返回处，比让每个调用方自己记得先赋值可靠。
- **`guards.js` 引用了已被删除的 `X_LIMIT` / `Z_LIMIT`。** 玩家改成按区域取
  `state.bounds` 之后，那两个常量就没了，但保安生成还在用它们 ——
  一打老师就 `ReferenceError`。改成读 `state.bounds`，两头共用同一个契约。
- `tools/smoke.mjs` 的 THREE 桩缺 `DirectionalLight` / `FogExp2` / `Color.lerp` /
  `Vector3.setScalar` / `Mesh.clone` / `Object3D.rotateZ`，逐个报"不是构造函数"。
  现在由桩覆盖度自检一次列出。
- 跳跃断言在 `animate()` 循环里偶发失败（8 次里错 1 次）：桩的 `Clock.getDelta()`
  读真实墙上时间，而测试循环跑得比真实时间快，每帧 `dt` 极小、跳跃永远走不完。
  改成直接喂确定性的 `dt` —— 那才是在测物理，不是测机器速度。
- **`browsercheck.mjs` 把调试端口写死成 9333，于是随机失败。** 上一次的 Chrome
  还没退干净时端口仍被占着，新实例根本起不来监听，报 `Chrome 调试端口没起来`
  （实测 8 次里 1 次）。更阴险的是端口被占时 `/json/list` 其实**会成功返回**，
  只是返回的是上一个实例的 target —— 那就不再是失败，而是连错页面。
  改成 `pickFreePort()` 向系统要一个空闲端口。这条不是游戏 bug，但它让
  "多跑几次"这个最有效的手段本身变得不可信，所以必须当成 bug 修。
- **`campusFlow` 探针偷偷依赖"上一段测试把相机留在合适位置"。**
  两次 `await evaluate` 之间会让出事件循环，**真实的 rAF 主循环会在缝隙里跑几帧**，
  按当时玩家的位置刷新 `camera.matrixWorld`。而 `updatePlayer()` 只改
  `camera.position/rotation`、不刷新矩阵，射线读的仍是上一帧那份。
  它一直能过，只因为前一个 reach 测试刚好把玩家停在门口 1m 处；
  加了"跑路"探针、把玩家挪到校门外之后，这条隐藏依赖立刻变成
  "门口按 `E` 没反应"。修法是每个探针自己 `camera.updateMatrixWorld(true)`。
  **探针之间不许有隐式依赖。**
- **「跑路了兄弟」用校门线判，结果谁都触发不了。** 最初的判定是"从门内穿过
  出门线（本地 z=9.5）"的穿越事件 —— 理由是出生点 z=11.5 本来就在门外，
  按坐标判会白送成就。但正因为出生点在门外，玩家**开局掉头往外跑**时
  z 从 11.5 一路涨到 15.2，永远穿不过 9.5，成就根本不可能触发。
  我的测试是直接改 `state.pos.z` 造的穿越，当然过；真按 `S` 走一遍立刻就露。
  现在改成"跑到校园可走范围的最外沿"（边界从 `AREA_BOUNDS` 取，不另抄一份），
  任何人往校外跑到头都会触发，触发后被拎回校门口。
  **教训：测"函数能不能触发"和测"玩家能不能做到"是两件事。**
- **快捷栏按 1-4 / Q 全都不生效。** `keydown` 里 `if (state.view !== 'world') return;`
  在背包视图下把**所有**键都拦掉了，包括用来关背包的 `B` ——
  于是"按 B 打开"能开、`B` 却关不掉，只剩 `Esc` 和按钮。玩家会以为卡住了。
  背包单独路由 `KeyB`。
- **`smoke.mjs` 的元素 id 表是手写的，加新 UI 必漂。** 它维护着一份
  `index.html` 里所有 id 的数组，注释自己都写着"加新 UI 时记得同步这里"。
  加背包面板时果然忘了，整轮测试变成二十来条
  `Cannot read properties of null`，报的错完全指不到真正原因。
  改成直接从 `index.html` 抠 `id="..."`，再并上手写的补充项。
- **探针改文件把 LF 变成了 CRLF、还加了 BOM。** 用 PowerShell 的
  `Get-Content | Set-Content` 改源码，除了行尾被整套换成 CRLF，
  `-Encoding UTF8` 还会加 BOM。功能上没事，但仓库约定是 LF 无 BOM，
  这种"看不见的改动"会污染后续所有 diff。已全部归一；改源码只用
  `edit` / `write` / `apply_patch`，批量场景用 .NET 显式 UTF8 读写。
  **同一个坑踩了三次**，第三次是 `[System.IO.File]::WriteAllLines` ——
  它按 `Environment.NewLine` 拼行，在 Windows 上就是把整个文件转成 CRLF。
  要按行批量改，得自己用 ``"`n"`` 拼成一个字符串再 `WriteAllText`。
- **`browsercheck.mjs` 第 9 节之后一直在校园区域里跑。** 校园段结束时有一句
  `switchArea(s.area)` 做还原，注释写着"后面的打老师要在房间区域里跑"，
  但 `s.area` 是进校园段**之前**抓的，也就是 `'campus'` ——
  代码和注释正相反。这几个探针都不读 `state.area`，所以一直没人发现；

  现在显式 `switchArea('room')`。
  **教训：注释里写的意图，得有断言盯着才算数。**
- **补给点坐标不能凭感觉摆。** 桌椅、四面墙、饮水机都是碰撞体，
  补给点摆进去就永远捡不到，而且没有任何报错 —— 东西在那儿，就是不响应。
  `smoke.mjs` 里有一条断言把三个点逐个丢进 `collides(x, z, PLAYER_RADIUS)`
  验一遍，摆歪了立刻报「落在障碍里，人走不进去」。
- **用光一摞之后再捡到同种东西，物品栏里看不到它。** 玩家实测报的：
  打死保安掉了一瓶臭水，屏幕提示「捡到「臭水」×1」，物品栏却是空的，
  按 `Q` 只回一句「这一格是空的」。
  两个行为单独看都正确 —— `bagTake` 用光后清空格子（不清就是死槽）、
  `bagAdd` 只往背包里加（它不管快捷栏）—— 但**串成一个循环就出事了**：
  东西确实在背包里（`bagIds` 有），只是挂不回物品栏，所以看不见也用不了。
  现在 `bagAdd` 会把物品塞进第一个空格。
  **教训：测了"用光会清空"和"捡到会 +1"，不等于测了"用光再捡"这个循环。
  两条各自正确的行为，组合起来可以是 bug。**
- **上面那条的第一版修法是错的：它让玩家边挨打边开背包。**
  第一版在"四格都占着"时提示「快捷栏满了，按 B 装上去」。
  可这游戏里物品只有 3 种、快捷栏 4 格，而且 `assignToHotbar` 用交换实现、
  从不产生重复 —— 所以**正常玩根本到不了"满了"**。那个状态是我自己手写
  `['stink','water','water','stink']` 造出来的假想敌，
  我却为它写了句要玩家办手续的提示：保安正追着你，让你开面板整理物品，
  等于告诉你刚捡的东西现在用不了。
  现在改成两条：`normalizeHotbar()` 在读档时把快捷栏去重并补齐到 4 格，
  保证"格数 > 种类数"这个不变式成立，于是永远留着一格；
  真的被改成坏形状时，静默把**当前选中那一格**让出来，提示里只顺口说
  「换下了「矿泉水」」，要求玩家做的操作是零。
  **教训：给"不可能发生的状态"写用户提示之前，先证明它真的发生不了 ——
  否则你写的不是兜底，是给玩家派活。**
- **"老师会瞄一眼你的屏幕"写了等于没写，因为打开电脑会让他停住。**
  `updateTeacher()` 挂在 `if (inWorld)` 分支里，而 `inWorld = state.view === 'world'`。
  也就是说：你一旦打开电脑桌面、IDE、草稿纸、背包 —— 老师整个人冻结在原地，

  你打开电脑的那一刻就等于按了暂停键。
  现在面板视图下走 `updateTeacherWhenPaused(t)`，只推进巡逻走位、只跑那一眼，
  模式机（走过来抓人那套）仍留在 world 分支里 —— 否则你开着面板时
  他会突然弹一个世界空间对话框出来。
  **教训：设计一个"NPC 观察你"的机制，先确认那个视图下 NPC 还在动。**
- **判定半径拍成 2.0，而巡逻轨迹到座位的最近距离是 2.5。**
  这一眼永远不会触发，而且不报任何错 —— 是量了才算出来的
  （轨迹是超椭圆 `|x/6.5|^0.7 + |z/5.5|^0.7 = 1`，离座位最近只到 2.5）。
  现在 `smoke.mjs` 里有一条断言采样 20000 个点求出最近距离，
  再拿它和 `TEACHER_PEEK_RADIUS` 比：半径小于最近距离就报
  「这一眼永远触发不到」。**任何"距离阈值 + 巡逻路径"的组合都该这样验一次。**
- **干扰同学推后 40 秒，对他的总分毫无影响。** 第一版就是这么写的：
  小红每道题之间隔 0.13 个比赛时长（约 31 分钟），推后 40 秒连一次交卷都跨不过去，
  终盘总分一模一样。现在改成推后比赛时长的 6%（约 14 分钟）——
  连着干扰 3 次刚好跨过一次交卷，正好卡在他起身告状的那个阈值上。
  **教训：调整一个"延迟/惩罚"参数时，要拿它和它要影响的那个间隔比一比量级。**
- **"HUD 没折行"这条断言，我连错了两次才写对。** 第一次量到 `高 0px` 就判"单行"——
  元素在 `display:none` 的祖先里时 `getBoundingClientRect` 全返回 0，那条断言是空过的。
  第二次改用 `h < 34` 当阈值，结果误报折行：这一行里有个 18px 的 `<b>`，
  **单行也有 44px**。第三次改成按矩形 `top` 去重数行，仍然误报 2 行——
  `18px` 的内联盒和 `13px` 正文的 `top` 差 2~3px，看着像两行。
  最终判据是**差分**：临时打上 `white-space:nowrap`，高度降下来了才是真折行。
  这个判据不需要任何像素阈值，也不受字体大小影响。
  **教训：断言"没有发生某件事"时，先证明这个判据在正常情况下不会误报，
  再证明它在异常情况下会报（给 `#hudScore` 加个 `max-width:240px` 验证过）。**

### 小恐龙那张脸：三个叠在一起的错误

小恐龙和仙人掌一开始"画得很丑"，拆开看是三处独立的错，每一处都不报错：

- **身体是个斜楔子。** 位图第 11 行最宽 25 格，第 23 行只剩 4 格 —— 不是身体，
  是从肩到尾巴尖的一个三角。腿画在第 23 行往下，于是长在一个 4px 宽的小揪上，
  其中一条腿（列 13..17）压根没有实体可接。扫成字符画一眼就看出来了：
  ```
  11 |#########################.......|   ← 最宽
  23 |..........####..................|   ← 收到 4px
  24 |..........###########...........|   ← 腿从这里长出来
  ```
  现在按"头 / 脖子 / 背 / 尾巴 / 平底肚子"重排，底行 14 格宽（列 7..20），
  盖得住腿的落点（列 13..20），两条腿都踩在实心上。

- **眼睛是瞎的，所以糊了个白方块。** `dinoDrawShape` 每行画 `s*sq + 0.6` 高，
  那 0.6 是为了让相邻行不留发丝缝 —— 但在整数行高下根本没有缝，多出来的
  0.6 反而**渗到下一行**，把 1 行高的眼白（和嘴缝）整个涂掉。
  于是只能另画一个 `3*s × 3*s` 的白方块顶替眼睛，位置还落在头的后半部。
  现在每行的上下边界单独 `Math.round()`：任何行高都不会留缝、也不会越界，
  位图里挖的洞就真的空着。断言直接逐像素验"这一格必须是背景色"。
  **教训：为了修 A 而加的余量，可能正好毁掉 B。补缝的余量要按行取整，不要靠加一个常数。**

- **仙人掌的"圆头"是同色矩形，手臂是飘着的。** 原来那句
  `fillRect(p.x+2, p.y, p.w-4, 3)` 画的是和主干同色的方块，在主干上等于没画，
  所以整株就是一根方柱子；侧枝从 `p.x-7` 起画，和主干之间隔 2px，看着像一根
  浮在旁边的横棍。现在四角切 1px 做真圆头，两只手臂用"肩 → 竖段 → 圆头"
  三段连着画，高低还错开，不再左右对称得像叉子。

- **顺带修了个会说谎的度量。** `dinomap.mjs` 把"腿顶 − 身体底 = 1px"标成"（有缝）"，
  但那 1px 是**相邻**（身体最后一个像素在 233、腿从 234 起），不是缝。
  老绘制因为多画 0.6px 才恰好等于 0 —— 换言之那个"0"才是假象。
  现在判据是"中间有没有空出一行"（差 ≥ 2 才算），并注入 `+2` 验证过它仍会报"差 3px"。

### 照着 Chrome 那只恐龙量一遍

"丑"是感觉，感觉不能当验收标准。所以把官方那只拆开来量：`dinosaur.game` 的页面里
内嵌了 Chrome offline 的雪碧图（base64 PNG），`spriteDefinition` 写明
`TREX: {x: 848, y: 2}`、`WIDTH: 44  HEIGHT: 47  WIDTH_DUCK: 59`，
动画帧按 x 偏移 0/44/88/132/220/264。写了个一次性 PNG 解码器（4 位调色板 + 反滤波）
把它打成字符画，得到骨架：

13 |......................##########............|   上颚收回

### 「正规入场」这个名字在编

这个成就不是工具抓到的，是有人玩的时候问了一句：**"正规入场？难不成还有不正规入场？"**
—— 问得对。名字里写"正规"，就是在默认存在一条"不正规"的路，而当时游戏里只有一条：
安检是硬的，没过安检楼门直接不放人（`passedSecurity`），根本绕不过去。
于是一个成就在指着一件不存在的事。

**第一版修得很敷衍。** 校门近端没有围墙，从柱子外侧绕进校园本来就是通的，
于是我把"跨门线那一下 |x| > 4.6"接成了成就 —— 技术上是真了，确实存在一条和正门不同的路。
第二天玩家回了一句：**"我蹭着边走就触发成就了，我还以为有侧门可以带手机溜入考场呢。"**
一句话指出两个问题：

- 这个成就奖励的是"路过"，不是"做了什么"。贴着墙根走两步就有，等于白送；
- 名字许诺了一扇侧门和一部手机，两样都没给。

**第二版才是把它当功能做。** 主楼东墙和围墙之间那条 2m 夹道本来就在（楼体半宽 11、
可走范围到 13），以前走到头是死路。现在尽头是员工通道的门，推开直接进考场那层，
**不过安检** —— 而安检正是"手机被收进密封袋"那一步。手机于是有了真实的分量：
它在兜里，按 `P` 能看每题得分 / 实时名次 / 剩余时间（HUD 上只有总分，看不出哪道题欠着）；
老师巡逻那一眼如果正好扫到你在看手机，当场没收 + 一次警告 + 「人赃并获」。

测试分两层：`smoke` 验状态机（侧门进楼后 `area` / `enteredRoom` / `passedSecurity` /
`hasPhone` 四个值必须同时正确，以及"没手机就掏不出来"的四种拦截），
`browsercheck` 用真实射线验"站在夹道里能不能瞄到那扇门"，再真的把弹窗点掉走一遍。
两处都做过反向验证：往侧门里注入 `state.hasPhone = false`、或者把 `'phone'`
从老师能看见的视图里去掉，对应断言会当场报红。

**教训两条：**
**① 「正规 / 正确 / 标准」这类词都在暗示一个反例。要么真有那个反例，
要么换个具体的名字 —— 描述你实际做了什么（手机被封存），别描述你没有违反什么。**
**② 成就得奖励"做了什么"，不是"走到了哪"。** 判定挂得再准，如果那件事本身就是白送的，
成就也只是噪音 —— 补上反例还不够，得让那个反例真的通向别处。

### 「没过安检，手机怎么没了」

玩家报的：走员工通道进来、没过安检，兜里却没有手机。

先量再猜：起了一个 headless Chrome 读真实页面的 `__OI__.state`，开局 `hasPhone` 确实是
`true` —— 所以不是初始化的问题。问题在**安检弹窗**。当时它有两个选项：

```
「走进教学楼」   → 过安检 + 收手机
「在原地愣一下」 → 也过安检 + 也收手机
```

两个都算"过了安检"，而且**没有第三条路**。玩家点「在原地愣一下」的意思是
"我还没决定"，结果手机没了、安检标记还变成"已通过"。之后他从侧门进来会发现
兜里没手机，而屏幕上没有任何地方告诉过他手机是在哪一步丢的 —— 于是很合理地被当成 bug。

三处一起改：

- 只有「把手机放进筐里，走进教学楼」会收手机；
- 多一个「先不过了」，**什么都不改变**；
- 弹窗正文不再提前写"你的手机被收进了密封袋" —— 还没选呢，那是假话。

顺带补了存档：`passedSecurity` / `hasPhone` / `sneakedIn` 以前不存，读档会出现
"过了安检手机又回来了"这种状态。`enteredRoom` 故意不存 —— 读档后区域还在校园，
存成 true 会把人卡在"进不去楼、也没法重新安检"的死角里。

断言直接盯着这个症状：「选了『先不过了』，手机却被收走了」。把老行为注回退路里，
它当场报这一句。

**教训：弹窗里每个选项都要么明确做事、要么明确不做，而且必须留一条完全不改变状态的退路。
「愣一下」这种含糊的标签，玩家读成"什么都不发生"，代码却在收他的手机。**

### 「别人的电脑打开后显示的是我的电脑」——三层，我只修了最上面那层

这条被报过两次。第一次我改的是"按 E 打开的那块面板"：以前所有同学共用
`state.npcProbId`，而它是**从你自己这局的四道题里抽的**，所以看谁的屏幕都是你正在做的那道。
改成按名字从整本题库算（`npcProblemId(name)`）之后——他打开还是自己的。

因为显示"电脑"的地方有三处，彼此独立：

1. **E 打开的面板**（`useNPCComputer`）—— 第一次修的就是这里；
2. **显示器贴图**（`drawDeskScreen`）—— 读的是 `state.problems / state.score / state.code`，
   而**全场 6 块屏共用这一个函数、这一份画布**。整屋子都在照镜子；
3. **交互动作本身**（`buildDesk` 里那句 `face.userData.interact`）—— 它给**每一张桌子**
   都挂了 `openDesktop()`，于是走到谁那儿按 E 打开的都是你那个 `CSP-S114514` 桌面。

现在每块屏、每个动作都带 `owner`：你自己那台叫「打开电脑桌面」，
其余五台叫「看一眼小明的电脑」，而且他坐着时动不了（`useNPCComputer` 拒绝），
走了才给看，面板标题是「小明的电脑」。

留个教训：**"某个东西显示错了"要先数清有几个显示点**，不能看见一个修一个。
这次的三个点分属 world.js / world.js / world.js 三处不相邻的代码，
靠改同一处编译不到一起去。

### 「带上武器怎么感觉更弱了」——因为它确实只多了个"会坏"

三把武器原来要占快捷栏，于是打架时得在「武器 / 水 / 臭水」之间来回切（玩家的原话：
"严重影响效率"），而多出来的好处只有拳锋变长——感觉不到，还得盯着耐久怕它散架。
**净收益是负的。**

改了两处：

- **武器不占快捷栏**：`state.weapon` 是独立一格，捡到即上手，HUD 显示「手持 扫把」。
  快捷栏回到纯消耗品。顺手把数字键从快捷栏上摘掉（`1`-`9` 只给弹窗选选项，
  切格改成滚轮）—— 一个键两种含义，迟早撞在"弹窗里按 2"上。
- **真击退**：没有被打倒的保安会被推开（拖把 2.0m / 扫把 1.6m / 板凳 1.2m / 空手 0.35m）
  并踉跄 0.45 秒；被抡倒的碎块速度按武器算（3.9 → 5.4/6.0/6.8），板凳砸下去飞得最远。
  通报会把击退说出来（"扫把抡倒 2 名，还推开了 1 名"），否则这效果玩家看不见。

### 「我怎么一直是第一名，从来没看见别人得分」

不是战斗时机的问题。五个对手的交卷时刻写死在 `pace × 4 小时` 上，`pace` 是 0.18~0.55，
也就是**最快的对手在赛程 18% 处才交第一题**。而比赛时钟 15 倍速、四道小题两分钟就能交完：

| 选手 | 首题交卷（比赛时间 / 真实时间） |
| --- | --- |
| 小刚 | 47 分钟 / 3.1 分钟 |
| 小明 | 82 分钟 / 5.5 分钟 |
| 小强 | 102 分钟 / 6.8 分钟 |
| 小红 | 118 分钟 / 7.9 分钟 |
| 小丽 | 139 分钟 / 9.2 分钟 |

**头 3 个真实分钟里五个人全是 0 分。** 你 2 分钟交完四题，于是从第 1 秒到结束都是第一，
屏幕上没有任何东西动过 —— 结论只能是"其他人不会得分"。

三处一起改：

- **节奏压进赛程前 ~37%**（`pace` 0.04~0.17，每题 +5%）。现在最快的 40 秒就开始交，
  2 分钟内有 4 个人在得分，3.3 分钟全员都交完。你出手快依然赢，但榜是活的。
- **名次一变就说出来**：`被 X 超过 —— 现在第 2 名` / `你超过了 X —— 现在第 1 名`。
  那个数字自己变太安静了，玩家的实际感受是"我一直第一"。
- **手机战况显示榜首是谁、多少分**：只写"第 6 名"看不出差距。

### 「保安怎么老刷在同一个地方」

同一个根因：`guardFreeSpot()` 从固定角度（`k = 0`，即 0 弧度）开始试，**第一个合法点
就返回**。于是同一批的两个保安、以及之后每一批，全都刷在同一个坐标上 ——
两个模型完全重叠，看起来就是"只刷一个地方"。

现在三件事一起做：

- 起始角**每批随机**，同一批的第二个用 `+π` 从对面包抄；
- 候选点必须离**已有保安**和**本批已选点**至少 2.4 米，凑不出就逐级放宽（1.4 → 0.6 → 0），
  绝不因为"太挤"就干脆不刷 —— 那会让 200 杀的开门口令永远凑不齐；
- 同一档里通常有多个合法点，**随机取一个**，不再永远挑第一个。

实测 12 批 × 2：同批最小间距 3.2~7.3 米，24 个刷点里 22~24 个位置互不相同，
离玩家最近 3.7 米。断言就是钉这两条：同批间距 ≥ 1.8 米、不同位置 ≥ 8 个
（退回"固定角度 + 取第一个"立刻报「24 个刷点只有 2 个不同位置」）。

顺带修正了两条被旧节奏带歪的测试：`被放倒的人不再交卷` 原来把放倒点设在赛程 40%，
压缩节奏后那时他早交完了（等于什么都没测）；现在设在 10%，并断言冻结值**等于放倒那一刻的分数**。
`干扰同学` 那条同理：现在量的是赛程中段的榜面（190 → 0，我的名次 6 → 5），
因为交卷不再摊到终点线附近，"拖后三次"不会再把谁顶出时限 —— 这一点已经写进注释，
免得下次有人以为它还该影响终盘。

### 「保安剩几个找不到」「人都死了还说他在座位上」「杀了老师手机不还我」

三条反馈，三个独立的根因：

- **保安找不到。** 增援是"围着玩家撒一圈"刷出来的，撒进去的位置从来不判碰撞。
  `updateGuards` 是逐轴判碰撞地走的 —— 整个人一旦陷在课桌/讲台里，两个轴都撞，
  他这辈子都不会再动，但 `alive` 一直是 true，于是 HUD 上永远挂着「⚠ 保安 1」。
  而开门条件是打满 200 个，所以那一个卡住的保安能**卡死整局**。
  现在 `guardFreeSpot()` 撒点必判 `collides`，整个考场都站不下就干脆不刷；
  已经被挤进去的由 `unstickGuard()` 按 0.4→2.6m 五圈十六向找出路，
  实在出不来（1.2 秒）就换到能站的地方 —— 找不到活人比"瞬移一下"严重得多。
- **人被打倒了还说"他还在座位上"。** `useNPCComputer()` 只认 `away` / `walking_away`
  两个状态，`down` 落到 else 分支里，于是对着躺地上的同学按 E 得到一句
  "他还在座位上，你不好动手"。现在 `down` 也算"人不在"。
- **打倒监考老师，手机不还。** 手机被没收后 `hasPhone=false` 且背包里那部被删，
  打老师这条路径从来没把它加回来。现在 `recoverPhoneFromTeacher()`：
  判 `state.hasPhone`（不是 `bagCount` —— `confiscatePhone` 是两样一起清、
  `reconcilePhone` 读档再对齐一次，两份状态始终同值），
  还回 true/1，且**重复调用不会变成两部**。

三条都配了断言，并且都做了"注入 bug → 看它报错"的反向验证。
保安那条第一版是不能咬人的：只断言"刷出来的都没卡住"，在撒点恰好避开桌子时
能蒙过去；补了一条"整个考场都堵死时 `guardFreeSpot()` 必须返回 null
且一个都不许刷"才真正钉住那个碰撞检查。

顺便记一笔：`collides` 用的字段是 `hd`（`{x,z,hw,hd}`），不是 `hh`。
测试里注入假障碍物时写错这一位，`o.hd + r` 就成了 `NaN`，`collides` 恒为 false ——
表现是"注入的墙根本不存在"，而断言看起来还在正常工作。

### 「开始界面的滚轮用不了，进入考场按钮还点不到」

两个毛病，同一个现场：

- `#start` 是 `position:fixed; inset:0; overflow-y:auto` 的一整块。介绍卡片 + 设置项
  比视口高（实测 1030px vs 624px），「进入考场」被推到折线以下 231px —— **必须滚才点得到**。
- 而滚轮在 `main.js` 里被快捷栏的监听 `preventDefault()` 了：那条判断只看
  `state.view === 'world'`，可开始界面本来就是 `world` 视图。于是滚轮一动不动、
  按钮还在下面，玩家只能得出"滚轮坏了、按钮点不到"。

修法：`#start` 改成 flex 列 + `overflow:hidden`，只有中间的 `.card` 自己滚
（`min-height:0` 是 flex 子项真的能收缩的前提，少了它等于没做）；滚轮监听补上
`!state.started`，比赛没开始就把滚轮原样交还浏览器。现在 624px 高的窗口里
按钮稳在 `top=495..541`。

`browsercheck` 钉了四条：按钮完整在视口内、页面不用滚、`#start` 自己不用滚、
开始界面上滚轮不许改 `hotbarIdx`。把布局退回旧写法 + 去掉滚轮那道门，
立刻报三条（`btnTop=855`、`1030 > 624`、`wheelStole`）—— 断言确实会咬人。

### 每跑一次测试就往 %TEMP% 里漏 17MB

`browsercheck.mjs` 会给 Chrome 开一个临时 profile，跑完删掉。它本来就有清理：
`removeProfile()` 重试 10 次 + `process.on('exit')` 兜底。结果每次跑完还是留一份
16~17 MB 的目录 —— 而且**退出码是 0**，脚本自己一声不响。

根因：Windows 上 `chrome.kill()` 只结束启动器进程，渲染进程和 crashpad 还活着，
继续攥着 profile 里的文件句柄；`exit` 钩子只能是同步的，重试几次等不到句柄释放，
脚本就退出了。几百毫秒后句柄自然释放，可那时已经没人去删了。

修法两条：① 用 `taskkill /T /F` 杀整棵树，再等 400ms 才删；
② 开跑前把 **30 分钟前**的 `oi-cdp-*` 顺手扫掉 —— 只动旧的，免得删掉并行在跑的另一份。
这是真正的兜底：不管上一轮怎么漏的，下一轮都会收走，并且会打一行字说出来。

**教训：清理逻辑写在"正常退出"路径上是不够的 —— 要问一句"如果进程被别的东西
拖着不放，我这个清理还有效吗"。以及，退出码 0 不代表没留下垃圾。**

## 玩法闭环

### 第一段：从校门口走到考场

1. 你从**校门口的砖路**上开始（第 114 中学）。往前是**第三教学楼 B 栋**，
   楼门口挂着牌子：**404 教室 · 考场 39**。路边的志愿者会告诉你该去哪栋。
2. 校门旁边有一圈**传送光圈**（旁边立着牌子「站上来 · 按 F」）。
   站到圈上按 `F`，直接瞬移到教学楼门口 —— 想省掉走路就用它。
3. 到楼门口先**过安检**（按 `E`）。保安扫一下准考证、把手机收进密封袋。
   墙上写着「已到 47 人，未到 1 人（就是你）」。**没过安检进不去教室。**
4. 安检通过后按 `E` 进 **404 教室** —— 这时才切进考场，比赛正式开始。

走不动的时候沿砖路走就行，准星会告诉你离教学楼还有多少米。

> **你也可以反过来跑。** 走进校园之后再掉头从校门口跑出去，会弹成就
> 「**跑路了兄弟** · 从校门口往外跑出去 —— 出发之后记得回来」。
> 判定不是"穿过门线"，而是"贴到可走范围的最外沿"（z = 15.2，差 0.8 就算）——
> 因为出生点本来就在门外（z = 11.5）：最初写的是"从门内穿出去"的穿越事件，
> 可玩家开局掉头往外跑时 z 是从 11.5 涨到 15.2，永远穿不过那条线，成就根本触发不了。
> 现在你会被志愿者一把拽回门口。
>
> **校门只立了两根柱子，近端没有围墙。** 柱子（含门卫室）挡得住正面，
> 挡不住侧面 —— 从柱子外侧（|x| > 4.6）绕进校园是通的。
> 但这只是"绕进校园"，不算入场，也不给成就 —— 真正的入场在楼门口。
>
> **员工通道（侧门）才是那条不正规的路。** 沿主楼东墙一直往北走，
> 楼和围墙之间有一条约 2m 宽的夹道，走到头是扇没上锁的铁门 ——
> 门上贴着「考试期间封闭」，落款是去年的。推门进去就直接到了考场那层，
> **不用过安检**。代价是没有代价，收获是：安检机的密封袋没碰过你的手机。
>
> 风险在老师身上：他巡逻时那一眼（每圈约 3 秒会扫到你）如果正好看见你在看手机，
> 当场没收，记一次警告，解锁「人赃并获」。手机没了之后按 `P` 只会提醒你去正门那边找。
>
> **入场有截止时间：开考 30 分钟（比赛时钟，约现实 2 分钟）后封场。**
> 校园里的提示一直挂着倒计时 ——「入场还剩 12 分」；剩 3 分钟时广播会响一次。
> 封场之后两条路都进不去（侧门也封），走到门口只会看到警戒线和保安一句
> 「早关了」，本场按**缺考**收场，结算标题就是这两个字。反过来，
> 踩着最后 3 分钟冲进去会解锁「**压线进场**」。
>
> **武器。** 三把，都在背包里（按 `B` 指派到快捷栏，之后**左键 / Q** 就是抡）：
> 空手拳锋 2.2m、半角 0.40；武器改的就是这两个数，外加耐久 —— 抡断了当场散架。
>
> | 武器 | 拳锋 | 半角 | 耐久 | 从哪来 |
> | --- | --- | --- | --- | --- |
> | 扫把 | 2.2 + 1.1 | 0.55 | 14 下 | **只有走员工通道才拿得到**（走廊里那堆） |
> | 拖把 | 2.2 + 1.4 | 0.45 | 10 下 | 考场后墙角落的固定补给点 |
> | 板凳 | 2.2 + 0.7 | 0.75 | 22 下 | 窗边的固定补给点 |
>
> 取舍：拖把够得最远但扫得窄，单挑最稳；板凳够不着多远，可半角接近直角，
> 被围住时抡一圈就是一片，还最耐；扫把居中，竖着抡能一次扫到两个。
> 保安的拳头比空手拳锋短，所以"先够到"本身就是活命手段。
>
> 顺带一句和剧情有关的小事：短信里要是有人说"刚看见有人从员工通道上来了"，
> 那是你 —— 只有 `state.sneakedIn` 为真时这条才会出现。
>
> ### 手机（按 `P`，得先把手机带进考场）
>
> 手机是**背包里的真物品**（`ITEMS.phone`），不是凭空的一个开关：开局就在背包里，
> 过安检时 `bagTake` 会把它真的拿走，被监考抓到也一样 —— 所以"背包里没有却能按 P"
> 这种事不会发生（`reconcilePhone()` 在读档后还会把两份状态对齐一次）。
> 它标了 `keep: true`：用一次不会少一台。默认**不占快捷栏** ——
> 快捷栏必须一直空着一格，那是"捡到的东西一定放得下"的前提；
> 想按 `Q` 打开的话，按 `B` 从背包里把它指派到某一格。
>
> 四个"软件"，切 tab 时**每次都重新渲染**（不然看到的会是打开那一刻的旧数据）：
>
> | 软件 | 内容 | 为什么留着它 |
> | --- | --- | --- |
> | 战况 | 每题得分 / 实时名次 / 剩余时间 | HUD 上只有总分，看不出哪道题还欠着 |
> | 群聊 | "考场交流群"，对手每交一题冒一条 | 消息由 `rivals.js` 的同一份数据推出来，和榜单不会打架 |
> | 2048 | 真能玩：方向键 / WASD 移动，R 重开 | 夹带进来的手机总得能干点什么 |
> | 计算器 | 四则 + 括号，真的能算 | 同上 |
>
> 群聊最上面永远钉着一句 **Cherry_Pop：「又在摸鱼呢？」** —— 它按"你此刻在干什么"排，
> 不按时间排。所以它是 `unshift` 上去的（丢进时间序会被"最近 9 条"挤掉），
> 而且不打时间戳：上面写着更晚的时刻、下面却是更早的消息，看着像 bug。
> 渲染成 `.pn-msg.pin`，左边一道竖线。
>
> 2048 是纯状态机（`g2048Move` 不改入参、没有定时器、`rng` 可注入），
> 所以测试直接喂盘面断言合并结果：`[2,2,2,2]` 左移得 `[4,4,0,0]`、`[4,4,8,8]` 得 `[8,16,0,0]`、
> 已经贴着左边时 `moved` 必须是 `false`（不然每按一次都白刷一个方块）。
> 在考场里合出 2048 会解锁成就「2048」。

### 第二段：考场里

1. 坐在自己的电脑前按 `E` 打开**桌面**（文件夹 `CSP-S114514`）。
2. 文件夹里正好是这一局抽到的**四道题**（文件名就是你要交的文件名），
   双击任意一道进评测环境，`提交评测` 拿分。
3. 同一个文件夹里还有一个 `dino.exe` —— 双击就是那个**断网小恐龙**。
   空格 / ↑ 跳，↓ 蹲，撞了就重来，最高分存在 `state.dinoHigh` 里。
   （如果你真的去玩了，会被成就「摸鱼选手」记一笔。）
4. 四道题每题满分 100，判题器是启发式的（见下），认真写能拿满分。
5. 离开座位超过 2 秒 → 监考老师走过来口头警告；累计走动 5 次 → 成绩直接取消。
   注意：**校园阶段走路不算违纪**，规矩只在进了 404 之后才生效。
6. 想看别人的代码：`F` 干扰同学 3 次，他起身去告状，趁他不在按 `E` 用他的电脑。
7. 打监考老师（正面对准按左键）→ 你有了血条，同时两名保安冲进来。
8. 每打倒一名保安补两名，最多 200 名。打满 200 → 走廊尽头那扇门开了。
9. **背包里那三样东西是你的底牌**（`1`-`4` 选、`Q` 用、`B` 开背包）：
   **臭水** ×3 扔出去，落点 2.6 米内的保安全蹲下干呕 2.6 秒 —— 这期间不追、
   不抓、也不扣血，拳头可以慢慢补；**矿泉水** ×2 回一格血（得先有血条）；
   **辣条** ×2 六秒内疾走快 35%（走路不受影响）。
   开局就配发 —— 安检收了你的手机，没翻你的包。
10. **地上散着补给，走近就自动捡**（不用按键）。考场里有三个固定点：
    饮水机旁的纸杯（矿泉水）、后排空位上的书包（辣条）、窗台下的备用瓶（臭水）。
    捡它们要离开座位，而离开座位是要拿违纪次数换的 —— 打老师之前先想清楚。
11. 打起来之后补给也自己会送上门：**每打倒 3 个保安掉一瓶臭水，每 5 个掉一瓶矿泉水**。
    节奏是固定的，不是随机 —— 打得多，控场和回血就跟得上。
12. 走到白光里 → 隐藏结局「一人军队」。

### 名次：赛场里另外五个人

13. 考场里另外 5 个人**不是布景**。每人按自己的节奏交卷：小刚 18% 时间就抢交
    （但糙，四题合计 210），小红写到最后 88% 才收工（370，全场最高）。
    所以**榜是活的** —— 半程时小刚领先，终盘小红反超。HUD 上一直显示你的名次。
14. 交完卷会排榜：六个人，你的那一行带箭头。清屏 400 分是第 1，320 分是第 3，
    200 分垫底 —— 光看「320 / 400」你根本不知道自己算强还是弱。
15. **干扰同学现在真的能拉低他的名次**：每干扰一次，他后面所有交卷时刻整体推后
    比赛时长的 6%（约 14 分钟）。连着干扰 3 次正好让他掉一道题 —— 而 3 次也正是
    他起身去告状的阈值，于是「惹毛他 → 他离开 → 你偷看他的代码 → 他回来已经落后」
    闭成一个环。被放倒的人当场停止交卷。

### 老师的那一眼

16. 监考老师巡逻时会瞄一眼你的屏幕。**开着电脑桌面（小恐龙、乱翻文件夹）或者
    正翻同学电脑时，他正好踱到座位旁**（3.4 米内），他就站住把显示器给你关掉，
    记一次警告。他每绕场一圈（约 42 秒）只有约 3 秒会进到那个范围 ——
    所以摸鱼不是不行，是要挑他不在附近的时候。
17. 写代码不会被抓；走动仍归那套「5 次违纪」管着。两套规矩互不干扰 ——
    这一眼只盯摸鱼，不冤枉人。

## 判题器怎么算分

浏览器里没法真编译真跑数据，所以用一套**可解释、可复现**的启发式。同一份代码
反复提交分数完全一样（种子里有代码本身），不能靠刷提交碰运气。

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| 关键字密度 | 0–40 | 命中题目相关关键词，每个 +3 |
| 代码长度 | 0–30 | 8 行起步，108 行封顶 |
| 结构完整度 | 0–30 | `main` / 输入 / 输出 / `return 0` 四件套 |
| 算法进阶 | 0–10 | 二分、前缀和、记忆化、并查集、堆、取模…… 各 +2 |
| 确定性抖动 | ±10 | `hash(代码 + 题目 id)` 作种子 |

基础分钳到 100，再映射到 10 个测试点。分数低于 10 → 0 分 WA；等于 100 → AC。
界面右侧会显示每条维度的得分明细，所以"为什么只有 40 分"是能自己看出来的。

## 与参考版本的差异

**新增**
- **整个校园段**：从第 114 中学校门口出发，沿砖路走到**第三教学楼 B 栋**，
  过安检，进 **404 教室**（考场 **39**）。路边的志愿者会告诉你楼号和教室号，
  墙上、门牌上、签到表上写的是同一组数字（都来自 `campusdata.js`，不散落硬编码）。
- **校门口的传送光圈**：站上去按 `F` 瞬移到教学楼门口。双层反向旋转 + 中心脉动光柱，
  旁边立着说明牌，小地图上也会画出来。
- **区域切换机制**：校园和考场是两块坐标错开的独立空间，切换只换"移动边界 + 障碍表"，
  **不销毁任何几何体**。换来的是来回切换零卡顿，也没有"重建世界时漏掉某个子系统引用"
  这类难查的错。代价只是内存里多留一份校园几何。
- **电脑桌面与 `CSP-S114514` 文件夹**：开机能进桌面，文件夹里正好是本局抽到的四道题
  （文件名就是你要交的文件名，进 IDE 就对上），双击即进评测环境。
- **能玩的小恐龙**：同一文件夹里的 `dino.exe`，canvas 手绘的 Chromium 断网小恐龙的复刻。
  跳跃 / 蹲下 / 仙人掌 / 翼龙 / 加速 / 最高分存档 / 防合成事件注入。
  跳跃初速与重力是按"最高速下滞空位移 ≈ 303px，最宽障碍 57px"调出来的，
  这条余量有单测覆盖。
- 3D 准星：`+` 变 `×`、攻击态放大红化、外圈视线停留进度环（极坐标 shader）。
- 保安队通报窗（10 杀起随机触发，四档递进文案 + 随机叛逆台词；嘴硬会推高紧张值并立刻加派人手）。
- 走廊"看见"了：尽头那扇门真的会在终局打开（门板摆动 + 白光 + 辉光 + 地面光斑 + 点光源）。
- 显示器贴图是活画布：提交、切题都会刷新，屏幕上能直接看到自己的得分状态。
- 键盘用了 Canvas 画键帽，省掉 96 个盒子。
- 假接触阴影（径向渐变贴片），随紧张值加深，比真 shadowMap 便宜一个数量级。
- 判题结果面板带**分项得分明细**，让评分逻辑可解释。
- 玩家座位中心、判题阈值、紧张值曲线等全部抽成命名常量，可单测。
- `tools/smoke.mjs` 无头测试与 `window.__OI__` 调试出口。

**改了做法**
- 后处理不用 `EffectComposer`/`AfterimagePass`，改成自研三通道 ping-pong，并在 blit 里显式做 linear→sRGB。
- three.js 加载改成 4 个 CDN 顺序探测 + 明确的失败提示页，而不是 ESM importmap 写死单一源。
- 时间拆成三条独立的线（realDt / 比赛时钟 / 世界时钟），顿帧与慢放只影响世界逻辑。
- 监考巡逻从椭圆参数改成超椭圆（指数 0.7），绕场轨迹更接近真实巡查。
- 老师 AI 拆出 `approach / warn / returning / patrol` 四态，并把"Esc 关掉警告窗后状态卡死"这个坑写进注释。
